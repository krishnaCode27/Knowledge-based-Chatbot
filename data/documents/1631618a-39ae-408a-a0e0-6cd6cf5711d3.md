# Knowledge AI — Technical Architecture & API Documentation

## 1. Architectural System Stack
Knowledge AI is engineered with modular microservices communicating over asynchronous gRPC and synchronous REST APIs:
* **Ingestion Worker:** Python 3.11 service utilizing `mistune` for CommonMark AST parsing and `tiktoken` for boundary chunking.
* **Embedding Model:** `text-embedding-3-small` (1536 dimensions) or local open-weights `bge-large-en-v1.5` (1024 dimensions).
* **Vector Database:** Qdrant Enterprise cluster running in distributed mode with HNSW indexing and payload filtering.
* **Lexical Index:** Tantivy / Elasticsearch 8.12 engine generating inverted indices for BM25 sparse matching.
* **Reranker:** Cohere Rerank v3 or local cross-encoder `bge-reranker-large`.
* **LLM Orchestration:** FastAPI backend running LangChain / LlamaIndex core with OpenAI GPT-4o or Anthropic Claude 3.5 Sonnet inference endpoints.
* **Caching Layer:** Redis 7.2 cluster storing query embeddings, session states, and cached top-5 responses (TTL: 3600 seconds).

## 2. Ingestion & Chunking Specification
* **Chunking Strategy:** Header-aware recursive character chunking.
* **Chunk Window Size:** **512 tokens** (~2,000 characters).
* **Chunk Overlap:** **64 tokens** (~250 characters).
* **Boundary Rules:** Chunks never split mid-table, mid-codeblock, or across first-level (`#`) markdown headers.
* **Extracted Chunk Metadata Schema:**
  ```json
  {
    "document_id": "doc_08_tech_doc",
    "filename": "08_technical_documentation.md",
    "header_path": ["Knowledge AI", "Ingestion Specification"],
    "chunk_index": 3,
    "token_count": 482,
    "last_modified": "2026-10-15T08:30:00Z"
  }
  ```

## 3. REST API Endpoint Reference

### `POST /v1/documents/upload`
Uploads and indexes a new Markdown document into the RAG corpus.
* **Request Headers:**
  * `Authorization: Bearer <API_TOKEN>`
  * `Content-Type: multipart/form-data`
* **Form Parameters:**
  * `file`: Binary file stream (`.md`, `.txt`).
  * `collection_id`: String (e.g., `"ait-campus-knowledge"`).
  * `tags`: Comma-separated strings (e.g., `"technical,api,architecture"`).
* **Response Body (`201 Created`):**
  ```json
  {
    "status": "success",
    "document_id": "doc_8f91b72e",
    "filename": "08_technical_documentation.md",
    "chunks_created": 14,
    "indexing_time_ms": 342
  }
  ```

### `POST /v1/query`
Executes hybrid retrieval, reranking, and context-grounded LLM synthesis.
* **Request Headers:**
  * `Authorization: Bearer <API_TOKEN>`
  * `Content-Type: application/json`
* **Request Body:**
  ```json
  {
    "query": "What is the token overlap used in document chunking?",
    "collection_id": "ait-campus-knowledge",
    "top_k": 25,
    "top_n": 5,
    "strict_mode": true,
    "stream": false
  }
  ```
* **Response Body (`200 OK`):**
  ```json
  {
    "answer": "The token overlap used in document chunking is 64 tokens (approximately 250 characters).",
    "citations": [
      {
        "document_id": "doc_8f91b72e",
        "filename": "08_technical_documentation.md",
        "section": "Ingestion & Chunking Specification",
        "chunk_index": 1,
        "score": 0.894
      }
    ],
    "retrieval_metadata": {
      "bm25_matches": 12,
      "vector_matches": 25,
      "rerank_time_ms": 48,
      "llm_latency_ms": 612
    }
  }
  ```

### `GET /v1/health`
Returns health telemetry for upstream dependencies (Vector DB, Redis, Embedding Service).
* **Response Body (`200 OK`):**
  ```json
  {
    "status": "healthy",
    "version": "2.4.1",
    "components": {
      "vector_store": "connected",
      "redis_cache": "connected",
      "embedding_worker": "online"
    }
  }
  ```
